1. src/lib/money.ts: spec says "round once at final persistence" but does not state the tie-breaking direction for exact .5 minor-unit remainders, and negative amounts (expenses) would round asymmetrically → resolved by using JavaScript `Math.round` (ties toward +Infinity: 10.5 → 11, -10.5 → -10); in practice all persisted values are integer minor units, so this only affects defensive handling of fractional inputs.
2. src/components/layout/sidebar.tsx: CHECKLIST says "click-to-toggle only (not hover, not outside-click)" while spec.md's UI/Layout section says outside-click collapses the sidebar → followed spec.md: the toggle (click, not hover) is the only way to open it, and it collapses on either the toggle again or a click outside the sidebar. The checklist line is read as "opening is not triggered by hover/outside-click".
3. src/lib/encryption.ts: spec mandates AES-256-GCM via `APP_ENCRYPTION_KEY` but never states the key's encoding/format → the existing `.env` value is 64 hex characters, so resolved to requiring a 64-hex-character (32-byte) key and rejecting anything else with a specific error; ciphertext is stored as `enc:v1:<iv>.<tag>.<data>` (base64url) so the dispatcher can tell encrypted DB values from plaintext env fallbacks.
4. src/lib/settings.ts: Item 1 says the Settings KV fallback chain for all keys ends in the Guardrail, but unlike `DEFAULT_CURRENCY` it never states what a missing `OPENING_BALANCE_<CODE>` means for the dashboard sum → resolved that a missing opening balance reads as 0 minor units (a well-defined zero opening position) while any caller needing a currency to exist still treats a missing `DEFAULT_CURRENCY` as the guardrail case.
5. src/lib/dates.ts: the schema stores `date` as an integer but the spec never defines the convention (epoch seconds vs YYYYMMDD vs epoch days), and dashboard month bucketing plus invoice/manual/import dates all depend on it → resolved to YYYYMMDD integers (e.g. 2026-01-15 → 20260115): timezone-free, sorts correctly, and month/year extraction is pure integer arithmetic; date strings are validated for 1900–2100 with real calendar days (no silent Date rollover).
6. src/lib/upload-guard.ts: the 15MB pre-base64 cap is stated for PDFs only and the rate-limit threshold/window is unspecified → applied the same 15MB cap to all accepted types (PNG/JPEG/WEBP/PDF), since images are the other runaway-cost path, and resolved the per-IP/session limit to 10 uploads per 10 minutes; both limits produce a specific client message and reject before any LLM dispatch or invoice row.
7. src/lib/invoices.ts: the version-update brief asks for both a stored source image and a dedup identity -> added a dedicated `content_hash` column for the sha256 digest and use `source_image`/`source_image_mime` for the uploaded bytes and MIME type; `raw_llm_response` continues to hold the raw LLM text because confirm must re-derive `suggested_category` from it. Migration 0001 moves legacy `sha256:` hashes into `content_hash` and nulls the old image field.
8. src/lib/import-map.ts: spec defines the direction precedence but not the mapped direction column's vocabulary, nor the fallback category for rows with no mapped category → treats {income, credit, in, be, bevétel, jóváírás, +, 1} (case-insensitive) as income and every other non-empty value as expense; a row with no mapped/empty category persists as "Imported".
9. src/lib/invoice-parse.ts: the brief sets a 100,000,000,000 minor-unit cap but does not state whether it is inclusive -> treated the cap as inclusive (`abs(value) <= 100_000_000_000`) for totals, net, VAT, gross, line items, manual entry, and invoice PATCH.
10. src/lib/invoice-parse.ts: the brief says invoice amounts may arrive as major or minor units and cites HUF as a zero-decimal currency, but the Intl heuristic calls HUF zero-decimal while the storage convention treats its minor unit as 1/100 Ft -> when `Intl.NumberFormat` reports `maximumFractionDigits === 0`, LLM major/minor amounts are scaled by 100 exactly once at the parse boundary, so stored minor units and `formatMoney` agree (e.g. 285 750 Ft -> 28 575 000 minor).
11. src/app/api/**: UI chrome is localized HU/EN, but server-side Zod/validation and legacy API failure messages remain English and are passed through as-is -> kept API messages stable and machine-readable; the surrounding labels, statuses, and helper text are translated in the UI.
12. tsconfig.json: the local `__eval__` shadow harness has older expectations and is not part of the shipped app -> excluded `__eval__` from `tsconfig.json`; the harness remains untracked and is not committed or required by `npm test`.
13. src/components/invoices/invoice-table.tsx: the brief asks for net/VAT/gross editing without saying how to resolve inconsistent input -> all three fields are sent; the server treats gross as authoritative when supplied, and the UI shows a non-blocking "Net + VAT != Gross" warning rather than silently rewriting the user's values.
14. src/app/api/reset/route.ts: the brief asks for a reset action but not its confirmation protocol -> require `{ confirm: true, confirmation: "DELETE" }` (case-sensitive exact token) so an accidental click cannot wipe the database, and the settings UI only enables the button after the token is typed.
15. src/lib/migrations.ts: databases from earlier builds may contain the three tables with no journal, a stale journal timestamp from an unrelated schema revision, or only part of the version-update columns, so a plain boot migration replays `CREATE TABLE invoices` or duplicate `ADD COLUMN` statements and crashes -> when the legacy tables exist, idempotently add any missing version-update columns, map legacy `net_total_minor`/`tax_minor`/`image_hash`/`image_data` values into the new columns, and record migration 0001 as applied before calling the migrator; later boots skip this normalization once all columns and the journal marker are present.
16. Dark mode/accessibility: the repo has no automated WCAG audit tool and the brief did not define a conformance target -> applied AA-oriented fixes (theme-aware chart line/grid/axis/tooltip, color-scheme for native controls, stronger focus/input tokens, skip link, focusable scrollable table regions, signed transaction amounts so direction is not color-only, chart text alternative/legend, labels and reduced-motion support); this is not a formal WCAG certification, and mixed Hungarian UI/English server errors (note #11) remain a known language-of-parts limitation.
17. src/lib/db-config.ts: the brief asked for one Vercel-style `DATABASE_URL` but did not define how the auth token travels with it → resolved that the token is embedded in the URL as `?authToken=...` (the libSQL client parses it), so the app reads exactly one database env var; the legacy `TURSO_DATABASE_URL`/`TURSO_AUTH_TOKEN` names and a separate `DATABASE_AUTH_TOKEN` are intentionally no longer read (existing env files must fold the token into `DATABASE_URL`). `DATABASE_URL` is added to diagnostics redaction because it carries the token.
18. src/lib/db.ts: `next build` imports every route while collecting page data, so a top-level connection both demanded `DATABASE_URL` at build time and opened a socket, failing the deploy before runtime env existed → the client is now a lazy proxy that resolves `DATABASE_URL` and runs migrations on the first query instead; since the root layout is `force-dynamic`, nothing touches the database during the build, and a missing `DATABASE_URL` surfaces at request time via the startup gate rather than crashing the build.
