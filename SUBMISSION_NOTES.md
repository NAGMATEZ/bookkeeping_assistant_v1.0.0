1. src/lib/money.ts: spec says "round once at final persistence" but does not state the tie-breaking direction for exact .5 minor-unit remainders, and negative amounts (expenses) would round asymmetrically → resolved by using JavaScript `Math.round` (ties toward +Infinity: 10.5 → 11, -10.5 → -10); in practice all persisted values are integer minor units, so this only affects defensive handling of fractional inputs.
2. src/components/layout/sidebar.tsx: CHECKLIST says "click-to-toggle only (not hover, not outside-click)" while spec.md's UI/Layout section says outside-click collapses the sidebar → followed spec.md: the toggle (click, not hover) is the only way to open it, and it collapses on either the toggle again or a click outside the sidebar. The checklist line is read as "opening is not triggered by hover/outside-click".
3. src/lib/encryption.ts: spec mandates AES-256-GCM via `APP_ENCRYPTION_KEY` but never states the key's encoding/format → the existing `.env` value is 64 hex characters, so resolved to requiring a 64-hex-character (32-byte) key and rejecting anything else with a specific error; ciphertext is stored as `enc:v1:<iv>.<tag>.<data>` (base64url) so the dispatcher can tell encrypted DB values from plaintext env fallbacks.
4. src/lib/settings.ts: Item 1 says the Settings KV fallback chain for all keys ends in the Guardrail, but unlike `DEFAULT_CURRENCY` it never states what a missing `OPENING_BALANCE_<CODE>` means for the dashboard sum → resolved that a missing opening balance reads as 0 minor units (a well-defined zero opening position) while any caller needing a currency to exist still treats a missing `DEFAULT_CURRENCY` as the guardrail case.
5. src/lib/dates.ts: the schema stores `date` as an integer but the spec never defines the convention (epoch seconds vs YYYYMMDD vs epoch days), and dashboard month bucketing plus invoice/manual/import dates all depend on it → resolved to YYYYMMDD integers (e.g. 2026-01-15 → 20260115): timezone-free, sorts correctly, and month/year extraction is pure integer arithmetic; date strings are validated for 1900–2100 with real calendar days (no silent Date rollover).
